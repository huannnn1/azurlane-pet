# B0 补充：坐标验证与画外机制

调研时间：2026-10-28。只加调试代码，未改行为。

## 1. 坐标空间：确认可用

改用库的 `internalModel.getDrawableVertices(idx)`（它内部做了 `× pixelsPerUnit + originalWidth/2` 换算），描边作为 `model` 的子节点挂载。结果正确：

`lafei_4`（画布 7000×7000）：

```
TouchHead    [3399, 935 - 4439,1886]   → 落在头部
TouchBody    [3023,2086 - 4780,4700]   → 落在身体
TouchSpecial [3459,2317 - 4432,2967]   → 落在胸前
停放在画外的网格数: 0 / 3
```

截图里三个框位置完全对得上（红=头、绿=身、蓝=特殊）。**坐标这一项不再是阻塞**。

顺带：描边线宽要用画布量级（45）才看得见，用 8 的话缩放后不足 1 像素。

## 2. 画外机制：确认存在，且比例很高

`benningdun_2`（画布 9600×5400）：

```
停放在画外的网格数: 68 / 72
TouchDrag1  [ 4628,-56786 -  5623,-55714]  ★画外
TouchIdle2  [ 6566,-31917 -  7578,-30786]  ★画外
TouchIdle3  [ 7581,-31913 -  8535,-30786]  ★画外
TouchIdle4  [ 6566,-30767 -  7579,-29697]  ★画外
```

这些区的 y 是 -3 万到 -6 万，而画布只有 5400 高——游戏把它们堆在画布上方的负坐标区，等于"停用"。只有 4 个区在画内。

**所以「画外 = 当前状态下不可用」这个判断是可用的**：鼠标永远点不到那些区域，天然被排除，不需要额外逻辑。

## 3. 状态激活：两种方式都试了，没成功

想验证"切到某个状态后，画外区会不会移进画内"：

| 尝试 | 结果 |
|---|---|
| 播 `touch_idle3` 动作后重扫 | 包围盒**完全没变**（仍是 -31913） |
| 直接 `setParameterValueById('touch_idle3', 1)` 后重扫 | 包围盒**完全没变**，画外数仍是 68/72 |

说明网格位置**不受**这两个东西控制。可能的机制：
- 由部件（part）变换或另一个参数组控制，不是 `touch_idleN` 这个同名参数
- 或者需要按特定顺序拉起多个参数
- 或者根本不是参数驱动，而是游戏代码在特定流程里动态改模型

**这一项没查出来。** 继续挖需要逆参数依赖，成本不可控，超出 B0 范围。

## 4. 对 B1 验收的影响（重要）

你给的验收条件是「benningdun_2 随机挑 3 个 TouchIdle 区和 2 个 TouchDrag 区各点一次」。

**这条现在做不到**：这些区默认停在画外，鼠标在窗口内怎么点都命中不了。能测的只有画内那 4 个区。

可行的验收改成：
- `lafei_4`：三个基础区全测（画内，已验证描边位置正确）
- `benningdun_2`：测画内的 4 个区，并验证画外的 68 个**不会**误命中
- Drag 区行为：找一个 Drag 区在画内的皮肤来测，或者先只验证"画外区不参与命中"

## 5. 对 B1 实现的影响

- **自动识别仍然有价值**：Head/Body/Special 三个基础区 **240/240 皮肤都有**，而且默认画内。接入后可以完全免掉手动标定，这是主要收益。
- **Drag/Idle 区暂时用不上**：需要先解开激活机制。B1 里按"画外过滤"自动排除，不特殊处理。
- **优先级规则照旧**：Drag/Idle > Special > Head > Body。虽然 Drag 区多在画外，但万一某个皮肤把它放画内，规则仍然生效。

## 建议

B1 按原计划做，但把「画外过滤」写进实现（包围盒完全在 `0~originalWidth/Height` 之外就跳过）。验收按第 4 节调整。Drag/Idle 的激活机制单独开一个调研项，不阻塞 B1。
